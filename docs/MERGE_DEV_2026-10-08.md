### Database version note

Upstream and this fork use the same version numbers for different schemas. Upstream `dev` is at
36 (its 34to35 adds `calibrationEntries`, its 35to36 rewrites `sourceSensor`). This fork was
already at 37 (it has `calibrationEntries` and `autoIsfValues`). So:

- `DATABASE_VERSION = 38`
- our `migration34to35` (MTR compatibility) and `migration36to37` (calibration) stay as they were
- upstream's sourceSensor rewrite is **`migration37to38`** here
- upstream's migration numbers are **not** this fork's migration numbers — see the note in
  `DatabaseMigrations.kt`

The rewrite is idempotent (the CASE keeps unknown names), so a row that already has a new name is
left alone. `LEGACY_SOURCE_SENSOR_NAMES` stays as the read-time safety net.

`migration34to35` is now in the `databaseMigrations` array. It was defined but missing from the
array before this merge.
