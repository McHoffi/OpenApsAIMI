## Translation loss and repair

The first merge pass took upstream's translation files, and it dropped the fork's own translations.
Reported by the user on 2026-10-26.

- Found: `core/ui` German went from 812 to 427 strings. French lost 105 in `plugins/main` and 50 in `app`.
- Repair 1 (`26cc2dcf49`): for every changed translation file, every string that was in the
  pre-merge file, is missing now, and still exists in the English file was put back. 594 strings.
- Repair 2 (`548acc8a1b`): 34 German strings for Settings → General and Appearance (units, language,
  simple mode, glass look, Vico chart, colour scheme). They had no German text before the merge either.
- Repair 3 (`de8830f15f`): 789 German strings from the fork history (every 15th first-parent commit)
  that exist in English and had no German entry. Mostly `core/keys`, `core/ui`, `plugins/aps`, `plugins/main`.
- Only German and English are kept up to date, as the user asked. Other languages were fixed only by
  repair 1. They may still miss fork strings.
- A restored German text can be old if the English text changed later.
- About 7600 English strings exist. About 3700 have a German name now. The rest stays English.

**Lesson for the next merge:** never take `--theirs` for a `values-xx/strings.xml` file. Merge by key
instead: keep upstream's text, and keep the fork's keys that upstream does not have. Compare the string
count of each translation file before and after the merge.
